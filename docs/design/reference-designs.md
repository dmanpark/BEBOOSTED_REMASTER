# BeBoosted UI Reference Set

These references are intentionally narrow. Each contributes one useful pattern; none should be copied as a complete visual system.

## 1. Notion Calendar — calendar restraint

[Notion Calendar](https://www.notion.com/en-US/product/calendar)

Use as reference for:

- Letting the week grid dominate the viewport
- Compact chrome and date controls
- Desktop keyboard/command ergonomics
- Keeping multiple calendar sources legible without turning them into cards

Do not copy:

- Monochrome neutrality so closely that BeBoosted loses its Academic Workbench identity
- Integration-heavy controls that are outside the first remaster

## 2. Sunsama — realistic planning and timeboxing

[Sunsama timeboxing](https://www.sunsama.com/features/timeboxing)

[Sunsama daily-planning flow](https://help.sunsama.com/docs/usage-guides/daily-planning/)

Use as reference for:

- Joining tasks and calendar availability
- Making workload feasibility visible before finalizing a plan
- Dragging tasks into time blocks
- Treating an internal calendar separately from connected calendars

Do not copy:

- The multi-column workspace density
- Mandatory daily rituals
- The number of navigation concepts and integration panels

## 3. Things 3 — progressive disclosure and completion quality

[Things 3 feature tour](https://culturedcode.com/things/features/)

Use as reference for:

- Hiding optional task fields until needed
- Clear, quiet task rows
- Smooth direct manipulation
- Making completion feel conclusive without adding gamification
- Fast desktop navigation while keeping visible structure understandable

Do not copy:

- Its list-first product architecture; BeBoosted must remain calendar-first
- The blue/white Apple-task-manager visual identity

## 4. Beli — adaptive relative ranking

[Beli on the App Store](https://apps.apple.com/us/app/beli/id1478375386)

[Beli's product story](https://beliapp.com/ourstory)

Use as reference for:

- Comparing two items instead of demanding an absolute score
- Adaptive follow-up comparisons
- A satisfying, low-explanation selection moment
- Turning subjective choices into a useful personal ordering

Change for BeBoosted:

- Include **Too tough to decide** as a real tie
- Scope ranks to Today or This week
- Keep deadlines and feasibility outside the subjective comparison result
- Avoid forcing comparisons between clearly inappropriate candidates

## 5. Linear — desktop speed and contextual detail

[Linear introduction](https://linear.app/learn/intro-to-linear)

[Linear Peek](https://linear.app/docs/peek)

Use as reference for:

- Fast keyboard-first actions that remain discoverable with the mouse
- Peek panels that reveal detail without navigating away
- Compact, consistent interaction states
- Command/search as an accelerator rather than the only navigation method

Do not copy:

- Enterprise issue-management density
- Dark surfaces, purple accents, or tiny low-contrast metadata

## 6. Fabric — mixed resource types inside a collection

[Fabric visual folder organization](https://fabric.so/features/kanban)

Use as reference for:

- Treating documents, notes, images, and links as first-class resources in one collection
- Giving resources recognizable previews
- Letting the same underlying content support different presentations later

Do not copy:

- Kanban as the default File view
- A global knowledge-management workspace
- Deep organizational complexity

## 7. Apple file-management guidance — familiar document behavior

[Apple Human Interface Guidelines: File management](https://developer.apple.com/design/human-interface-guidelines/file-management)

Use as reference for:

- Familiar add/open behavior on desktop
- Autosaving reference organization
- Clear document type and source identity
- Preserving confidence that user material remains available

Do not copy:

- A generic operating-system file browser
- Folder nesting or Finder-level file operations

## Recommended synthesis

Ask the mockup system to combine:

- Notion Calendar's spatial restraint
- Sunsama's feasibility-aware timeboxing
- Things 3's progressive disclosure
- Beli's pairwise decision interaction
- Linear's desktop interaction polish
- Fabric's mixed-resource legibility
- Apple's familiar file semantics

Then explicitly require BeBoosted's own signature:

- White/cream Academic Workbench
- Highlighter-lime AI proposals
- Tabbed Project Files
- Calendar-first application shell
- Provenance-backed planning explanations

## Reference guardrail

If a generated mockup resembles any single reference at first glance, revise it. The references provide interaction lessons; the white/cream/lime calendar-and-folio composition must remain original to BeBoosted.
